# Narrative Interact

> ⚠️ このプロジェクトは開発中です。予期しない動作やバグが起きる場合があります。

[English README is here](README_EN.md)

ローカルLLMで動くインタラクティブフィクションシステム。  
ジャンルとタイトルを入力するだけで、LLMがGM（ゲームマスター）として物語を自動生成する。プレイヤーは主人公として自由に行動を入力し、その結果に応じてGMが物語を進める。

あらかじめ用意されたシナリオを読むのではなく、LLMが生成した物語に主人公として介入し、自分の行動によって展開を変化させながら物語を進めるシステムです。プロットへの拘束度を選べるため、物語の流れを重視したプレイから、展開を積極的に変えるプレイまで試せます。

## 特徴

- **完全ローカル動作**：LM Studio経由でローカルLLMを使用。外部APIは不要
- **ジャンル・タイトル自由**：日常、ミステリー、ファンタジー、ホラーなど何でも指定可能
- **プロット自動生成**：ゲーム開始時にLLMが物語の骨格（登場人物・葛藤・反転・エンディング）を設計する
- **ダイス判定**：行動の成否をダイスで決定。成功・失敗がGMの描写に反映される
- **セーブ・ロード**：途中でセーブして後から再開できる
- **物語の軸を選択**：プロット拘束度を4段階から選べる
- **GMの一言**：転換点でGMがシニカルな一言コメントを返す場合がある。あり/なしを選択制
- **転換点描写強化**：物語の転換点で自動的に詳細な描写を促す（1ターンの目安300字を500字以内に拡張）。転換点ターンのGM本文は明るい黄色で表示される（GMの一言の設定に関わらず発動）

## 遊び方

### 1. 起動とゲーム設定

```bash
python main.py
```

起動後、以下を順番に入力する。

```
ジャンル: ミステリー
タイトル: 消えた遺言状
```

続いて物語の軸を選択する。

| 選択 | モード | 内容 |
|------|--------|------|
| 1 | プロット参照・強拘束 | 反転・選択・失敗をプロット通りに回収する。プレイヤーの行動の自由は維持しつつ、主要なプロット要素をほぼ回収する。**初めてならこれを推奨** |
| 2 | プロット参照・適応 | プロットに添うが逸脱プレイ可能。逸脱が大きい場合は現在地で物語を再構成し、着地まで誘導する。 |
| 3 | プロット参照・自由 | プロットは参考情報。逸脱しても構わない。プレイヤーの自由行動を最優先にしたい場合に向く。 |
| 4 | プロットなし・即興 | プロットを生成せずGMが即興で物語を作る。展開の方向性に制約がない。 |

続いてダイス判定を使うかどうか（Y/n）を選択する。使う場合は難易度（易しい・標準・厳しい）も選択する。

最後にGMの一言コメントのあり/なしを選択する。

| 選択 | 動作 |
|------|------|
| あり（シニカル） | 転換点でGMがシニカルな一言コメントを返す。「まあ、そういう手もあるか」「…そうですか」 |
| なし | GMは黙って進行する（従来の動作） |

**モードの違いについて**

各モードはGMへのプロット制約の強さが異なります。同じプレイヤー行動でもモードによって結末が大きく変わることがあります。これは設計上の意図的な差異です。

- **強拘束**：システムがGMにビート（場面の節目）をターンごとに注入し、プロット回収を強制する
- **適応**：逸脱検出をターンごとに行う。逸脱判定が累積3回で収束を促す指示を注入し、累積5回で新プロットをLLMに再生成させてbeat制御で着地させる（逸脱しないターンがあってもカウントはリセットされない）
- **自由**：プロットはシステムプロンプトに参考情報として渡すのみで、ビート注入は行わない。逸脱しても強制しない
- **即興**：プロット生成もビート注入も行わず、GMの出力のみで物語が進む

自由・即興・適応（再生成前）では、25ターンを超えると物語を収束させる指示がGMに注入される。

**GMの一言について**

GMの一言コメントは物語本文の生成とは独立した別の呼び出しで動作する。物語のルール・モード・ビート進行には一切影響しない。

転換点（プロット上の節目やLLMが転換点と判定したターン）のみGMが一言コメントを発する。毎ターン出るわけではないため、出たときに意味が生まれる。物語のジャンルや展開によっては転換点が少なく、一言コメントがほとんど出ない場合もある。

コンソール表示は `GM:` が青色、コメント本文がシアン色で `GM: まあ、そういう手もあるか` のように表示される。

### 2. 行動入力

GMの描写を読んで、主人公として行動を入力する。

```
> 机の引き出しを開ける
> 老人に話しかける
> 窓から外を見る
```

行動は自由。GMはプレイヤーの行動を否定せず、結果として世界を変化させる。

### 3. ダイス判定

ダイス判定を使う設定にした場合、行動によってはダイス判定が発生し、成否がGMの描写に反映される。難易度は起動時に選択できる（易しい・標準・厳しい）。

出目はPythonの`random.randint(1, 20)`で決定される。AIが判断するのは「判定が必要か」「行動のリスクと不確実性の分類」のみで、出目と難易度の数値にはAIは一切関与しない。

### 4. エンディング

物語の主要な葛藤が解消されるとGMがエンディングを描写して物語が終わる。

## 動作環境

- Python 3.10以上
- [LM Studio](https://lmstudio.ai/) （ローカルサーバーとして起動）
- 推奨モデル：Gemma4 12B
- 推奨コンテキスト長：32,768トークン以上（入力側：システムプロンプト約10,000トークン＋物語進行の会話履歴で計約30,000トークン。出力側：`MAX_TOKENS`はGMの1回の生成上限で、実際の出力は数百〜1,000トークン程度）

## セットアップ

バイナリ配布はありません。ソースコードをそのままダウンロードして実行してください。

```bash
git clone https://github.com/naoki-Kamishiro/narrative-interact.git
cd narrative-interact
pip install -r requirements.txt  # openai / json-repair
```

`config.py` でLM StudioのエンドポイントとモデルIDを設定する。

```python
# config.py
LM_STUDIO_URL = "http://localhost:1234/v1"  # LM StudioのデフォルトURL
MAX_TOKENS    = 1024                         # 1回の生成で出力する最大トークン数
TEMPERATURE   = 0.85
```

モデルIDの指定は不要（LM Studioはロード中のモデルを自動で使用する）。  
コンテキスト長（32,768トークン以上を推奨）はLM Studio側のモデル設定で変更すること。

## 自動プレイ（デバッグ用）

プレイヤー入力もLLMが担当するモード。プロンプト検証・挙動確認に使用する。

```bash
python main.py --normal           # 通常モード
python main.py --deviate          # 逸脱モード（GM制約を意図的に超える行動）
python main.py --debug            # 手動プレイ＋デバッグ出力あり
python main.py --normal --batch 5   # バッチ実行（ランダムなジャンル・タイトルで5回連続）
python main.py --deviate --batch 5  # 逸脱モードでバッチ実行
```

`--batch N` を指定すると、ジャンルを固定リスト（12種）からランダムな順で選び、タイトルをLLMが毎回自動生成してN回連続で実行し、1回ごとにJSONファイルを保存する。物語の軸・ダイス判定の有無・難易度・GMの一言は起動時に1回だけ選択し、全セッションで共通となる。

プレイヤーLLMの挙動はモデル・ジャンル・プロット設定に大きく依存する。特にジャンル制約で戦闘・探索・謎解きをすべてオフにした場合（群像ドラマ・日常など）、プレイヤーLLMが「見つめる」「近づく」などの行動を繰り返すループに陥りやすくなる。これはシステムのバグではなく、行動の選択肢が狭いジャンルにおけるモデルの素の挙動である。

自動プレイを研究・観察目的で使う場合、ダークファンタジー・ホラー・ミステリーなど探索や謎解きのあるジャンルの方が挙動の多様性が出やすい。

## モデルの性能限界（Gemma4 12Bでの妥協点）

より高性能なモデルでは改善する可能性がある。

**軽減策実装済み（確率的に発生）**

- **毎ターン問いかけで締める**：「あなたはどうしますか？」で締めくくる
- **選択肢の箇条書き**：「A. 逃げる　B. 戦う」のように選択肢を列挙する
- **ダイス判定の無視**：失敗を実質成功に描く、成功を直後に無効化する
- **局面への沈み込み**：同じ場面を掘り下げ続け、物語が進まない
- **NPCによる代弁・評価**：NPCが主人公の行動の意味を解説する、判断を称賛する
- **エンディング早発**：「帰宅した」などの日常描写で終わらせる

**残存する制約（対策後も一定頻度で発生）**

- **地の文への意味付け**：「覚悟が固まる」「これは○○を意味する」のような内面・解釈が混じる。後半やクライマックスで起きやすい
- **着地点の先取り**：プロットのendingにある動機語・テーマ語をエンディング前に使う。ミステリーで起きやすい
- **文字数の超過**：1ターン300字の目安を守らない。ジャンルによっては大きく超える

**モデル依存（完全な解消はモデルの能力次第）**

- **設定の追加先行**：既出の情報から結果を導かず、新しい設定・脅威・人物を足していく
- **効果量が均一に大きい**：出目の強弱にかかわらず、物語全体を揺るがす展開を起こす
- **ジャンル制約の無視**：戦闘禁止のジャンルでも、重大失敗などをきっかけに敵対的な展開を作る
- **未発生の代償の回収**：本編で起きていないプロット上の代償を、エピローグで既成事実として描く
- **プレイヤー入力の書き換え**：入力された行動を、辻褄合わせのために別の行動として描写する
- **フック回収の省略**：冒頭フックの回収（hook.closing）がエンディングで描かれないことがある

## 既知の不具合（自動プレイ時のプレイヤーLLM）

いずれもプレイヤープロンプトで抑制済み（対象の言い換えループのみ未対策）。完全な解消はモデル依存。

- **動詞を変えたループ**：「握る→握りしめる→力を込める」のように同じ対象への行動を繰り返す
- **対象を言い換えたループ**：「兵士A」「重装兵」のように呼び方を変えて、同じ集団への行動を繰り返す
- **失敗対象への固執**：失敗が続いても別の対象・場所に切り替えない
- **内面行動の出力**：「覚悟を決める」のような外から見えない行動を出力する
- **世界観外の手段**：医療ホラーで銃を使うなど、世界観にないアイテム・手段を持ち出す
